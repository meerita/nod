# Writing and documentation

* Write in US English.
* Use ASD-STE100 style where practical.
* Use short sentences.
* Use direct language.
* Use one instruction per sentence.
* Prefer active voice.
* Prefer concrete terms.
* Avoid unnecessary adjectives.
* Avoid vague references.
* Avoid rhetorical language.
* Avoid em dashes.
* Use Nod terminology consistently.
* Define new terms before repeated use.
* Do not use Unix terminology for native Nod concepts unless it is technically required.
* Do not describe planned behavior as implemented behavior.
* Keep documentation close to the code or subsystem that owns it.
* Do not duplicate documentation.
* Link to the owning document instead.
* Update documentation when behavior changes.
* Keep examples minimal.
* Make examples executable when practical.
* Do not use placeholder behavior in normative documentation.
* No emojis. No emdashes. Use plain text, parentheses and punctuation.
